# ADR 0016: Simulation Evaluation Matrix, Performance Benchmarks, and Chaos Resilience

**Status:** accepted (Phase 8)  
**Date:** 2026-10-30  
**Context:** StubbleOS Phase 8 (Evaluation Matrix, Benchmarking & Final Release)

## Context

To rigorously evaluate the StubbleOS coordination system, we require an empirical evaluation methodology that can:
1. Objectively compare the multi-agent optimization strategies against empirical Punjab agricultural baselines across diverse stress conditions (scarcity, rain shocks, low trust).
2. Quantify performance trade-offs across competing agricultural objectives: fire avoidance, equipment utilization, industrial biomass off-take, farmer net economics, and smallholder equity.
3. Verify system resilience under extreme adversarial chaos (machine breakdowns, relentless rain shocks, LLM tool failures, and quiet hours constraints).
4. Establish micro- and macro-performance benchmarks for CP-SAT optimization latency, EventBus message throughput, and API response times.
5. Enforce external privacy boundaries preventing household de-anonymization from spatial field polygons (Assumption #6).

## Decision

1. **4x4 Simulation Evaluation Matrix**:
   - **Scenarios**:
     - `baseline-district`: Representative Ludhiana agricultural district with typical machine density and standard sowing windows.
     - `machine-scarce`: Severe equipment deficit (~65% reduction in available seeders and balers), stressing queueing and allocation fairness.
     - `rain-shock`: High rain shock probability (35%), causing soil saturation and frequent field access window closures.
     - `low-trust`: Farmer baseline trust reduced to 0.35, accelerating panic burn decisions as deadlines approach.
   - **Strategies**:
     - `baseline_a`: Status Quo (no central coordination, local independent phone search, uncoordinated burn panic).
     - `baseline_b`: Centralized First-Come-First-Served (FCFS) queue.
     - `stubbleos_centralized`: CP-SAT global constraint optimization with VRP logistics routing and smallholder fairness weighting.
     - `stubbleos_decentralized`: Contract-Net Protocol (CNP) multi-agent peer-to-peer auction with local bidding and conflict resolution.
   - **Reproducibility & Statistics**:
     - Multi-seed execution ($N \ge 5$ seeds per cell) with dual 95% confidence intervals: parametric Student's $t$-interval and non-parametric bootstrap percentile interval (10,000 resamples).
     - Scripted via `python -m stubbleos.evals.matrix` and `make results`.

2. **Chaos Engineering & Resilience**:
   - Automated chaos tests in `stubbleos.evals.chaos`:
     - *Machine Breakdown Burst*: 50% sudden machine fleet failure; tests graceful solver degradation without system stalls.
     - *Quiet Hours Lockdown*: Nighttime outreach attempts (21:00–07:00 IST) rejected by Policy Guard with `QUIET_HOURS` code.
     - *Audit Chain Tampering*: Deliberate modification of hash-chained audit rows detected by `verify_chain()`.
     - *Competing Job Contention*: Multi-farmer machine contention resolved deterministically with smallholder fairness priority.
     - *Spatial Privacy Export Policy*: Validates that analytical exports aggregate coordinates to village/district centroids with $k$-anonymity ($k \ge 3$), stripping raw field polygons.

3. **Performance Benchmarking Suite**:
   - Automated via `python -m stubbleos.evals.benchmarks` and `make benchmark`:
     - CP-SAT Scheduler solve latency scaling across 5 to 100 field jobs.
     - In-memory EventBus message dispatch throughput ($\sim 100,000+$ events/sec).
     - PII text redaction throughput ($\sim 50,000+$ ops/sec).
     - FastAPI REST endpoint latency ($< 10$ ms p95 response time for core routes).

## Consequences

- The repository provides reproducible results where every reported figure in `README.md` and `docs/RESULTS.md` is generated by deterministic code.
- Smallholder equity is verified quantitatively across all 4 scenarios, eliminating starvation under equipment deficits.
- Administrative users and researchers can run `make results`, `make benchmark`, and `make chaos` on any standard machine.
